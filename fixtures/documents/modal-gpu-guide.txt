GPU Computing for AI Inference: A Practical Guide

Modern AI applications increasingly require GPU acceleration for tasks like embedding generation,
image classification, object detection, and large language model inference. This guide covers the
key concepts and trade-offs involved in deploying GPU workloads for production AI systems.

Embedding Generation:

Text embeddings convert natural language into dense vector representations that capture semantic
meaning. Models like OpenAI's text-embedding-3-small (1536 dimensions) or Sentence Transformers
(384-768 dimensions) can run on CPU for small batches but benefit significantly from GPU
acceleration at scale.

Image embeddings using models like CLIP (Contrastive Language-Image Pre-training) map both images
and text into a shared embedding space, enabling cross-modal search. CLIP-ViT-B/32 produces
512-dimensional vectors and requires a GPU for real-time inference.

Batch vs Real-time Processing:

Batch processing embeds large document collections offline. This tolerates higher latency and can
use cheaper GPU instances. A common pattern is to process a backlog of unembedded documents on a
schedule, then serve queries against the pre-built index.

Real-time embedding generates vectors on the fly during ingestion or query time. This requires
warm GPU containers with low cold-start times. Techniques like memory snapshots and model
pre-loading reduce initialization overhead.

Scaling Strategies:

Serverless GPU providers (Modal, fal.ai, Replicate) offer per-second billing with automatic
scaling. This is ideal for bursty workloads where demand varies significantly. Cold starts
typically range from 1-10 seconds depending on model size and container configuration.

Reserved instances provide consistent performance at lower per-hour cost but require capacity
planning. They are better suited for steady-state workloads with predictable traffic.

Hybrid approaches use serverless for burst capacity while maintaining a small reserved pool for
baseline traffic. This balances cost and latency.

Cost Considerations:

GPU costs vary significantly by provider and instance type. An NVIDIA A100 (40GB) ranges from
$1.50-$3.00 per hour depending on the provider. For embedding-only workloads, smaller GPUs like
T4 ($0.50-$1.00/hr) or L4 ($0.80-$1.50/hr) often provide sufficient throughput at lower cost.

The key metric is cost per 1,000 embeddings. At batch sizes of 256+ on an A100, text embedding
costs drop below $0.001 per 1,000 documents. For comparison, OpenAI's API charges approximately
$0.02 per 1M tokens for text-embedding-3-small.
